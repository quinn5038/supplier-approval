# 离线材料脱敏助手（脱敏助手v1.0）

> 制定时间：2026-09-04
> 改造依据：保密专员共识——供应商未公开披露的财报、类似法人身份证的敏感文件不能直接发给 AI 处理
> 实现模块：`desensitize.py`（新建，~190 行）

---

## 一、设计目标

把从 ICCEC 系统下载的供应商材料做**本地纯 Python 脱敏**，输出到 `cache_v4_desens/` 给 textin / AI 识别使用。

**核心原则 = 脱敏的本质**：本地完成，不调任何云端 OCR / AI——这是"脱敏"的安全基础。

---

## 二、四类文件处理策略

| 文件类型 | 处理方式 | 依赖 |
|---|---|---|
| **财报 PDF** | 保留数字表格（财务指标需要），打码人名/签字/银行账号 | PyMuPDF（缺库降级） |
| **身份证 JPG/PNG** | 保留国徽页（公开），整片打码人像页（姓名/性别/出生/住址/证号/头像） | Pillow |
| **营业执照** | 原样保留（公开信息） | 无 |
| **其他**（ISO/授权/声明） | 原样保留 | 无 |

**缺库绝不阻塞**：缺 PyMuPDF → 财报 PDF 原样复制 + warning；缺 Pill → 身份证原样复制 + warning。

---

## 三、身份证识别规则

通过两个判断条件识别身份证（**白名单**）：

### 文件名关键词判断
- 含 `身份证` /`证件` /`id_card` /`id_` 的文件名

### 文件名模式判断（**中文姓名**特征）
- 纯中文姓名 + 扩展名（` 李作发.jpg`）
- 数字ID前缀 + 下划线 + 中文姓名 + 扩展名（` `10091700300_李作发.jpg`）

### 排除规则（避免误识别）
- 文件名含常见材料关键词 → 不视为身份证：
  - 营业执照 / 营业 / 税务 / 纳税 / 信用 / 质量
  - ISO / 授权 / 代理 / 经销 / 声明 / 承诺 / 售后
  - 生产 / 许可 / 强制 / 3C / 检验 / 检测
  - 资质 / 证书 / 审计 / 财报 / 财务 / 报告
  - 专利 / 商标 / ICP

## 四、调用方式

### 命令行

```bash
# 把 cache_v4 整个目录脱敏到 cache_v4_desens
python desensitize.py --src cache_v4 --dst cache_v4_desens

# 自定义路径
python desensitize.py --src /path/to/files_cache --dst /path/to/output
```

### Python API

```python
from pathlib import Path
from desensitize import desensitize_dir, _desensitize_id_card_image

# 批量脱敏整个目录
desensitize_dir(Path("cache_v4"), Path("cache_v4_desens"))

# 单文件身份证图片脱敏
ok = _desensitize_id_card_image(src_img, dst_img)
```

### 与 textin_pipeline.py 集成（推荐路径）

在 `textin_pipeline.py` 的 OCR 处理前调用：

```python
from desensitize import desensitize_dir
from pathlib import Path

# 阶段1.5：先脱敏再OCR
src = BASE_DIR / "cache_v4"
dst = BASE_DIR / "cache_v4_desens"
desensitize_dir(src, dst)

# 然后 textin_pipeline 改读 dst 目录
```

## 五、实测效果

### 测试样本

- `files_cache/45339209/10091700300_李作发.jpg`（湖北科规法人身份证，546KB）

### 输出结果

- `cache_v4_desens/.../10091700300_李作发_desens.jpg`（脱敏后，333KB）
- **国徽页保留**：含"中华人民共和国居民身份证" + 签发机关 + 有效期
- **人像页整片打码**：姓名/性别/出生/住址/身份证号 `420601197111150036`/头像全部消失
- **马赛克化头像**：用 Pillow 缩小再放大 = 像素化效果
- **"[DESENSITIZED]" 水印**：图片中央浅灰文字标识

## 六、依赖与降级策略

### requirements.txt 列出的依赖

```
Pillow>=10.0          # 身份证图片脱敏（必装）
PyMuPDF>=1.23         # 财报 PDF 脱敏（可选）
```

### 缺库降级行为

| 场景 | 行为 | 用户感知 |
|---|---|---|
| PyMuPDF 未装 | 财报 PDF 原样复制 + WARNING 日志 | 不阻塞流程，但财报敏感信息泄露风险 |
| Pillow 未装 | 身份证原样复制 + WARNING 日志 | 不阻塞流程，但身份证敏感信息泄露风险 |

**风险提示**：缺库时敏感信息仍会泄露给 AI 处理。建议**生产环境必装 PyMuPDF + Pillow**。

---

## 七、局限性（未来改进方向）

1. **财报 PDF 脱敏精度**：当前用正则匹配敏感字段，遇到特殊排版（加粗/合并单元格）可能漏打码
2. **身份证布局假设**：按典型 4:3 比例估算，特殊扫描件可能错位
3. **无人脸检测**：用固定坐标估算头像位置，未用 OpenCV 等做真正的人脸检测
4. **未处理 Word/Excel 财报**：供应商有时上传 docx/xlsx 财报，暂未支持
5. **没有审计日志**：脱敏过程未写日志文件，事后无法追溯

## 八、对参赛演示的加分点

### 评委演示建议

1. **现场跑一次脱敏**：上传身份证图片 → 展示脱敏前后对比图
2. **强调"本地处理"**：这是"脱敏"的核心安全基础——数据不出本地
3. **强调"合规优先"**：不是所有事都让 AI 做，敏感证件人工核对是底线
4. **展示代码简洁性**：desensitize.py ~190 行，依赖最少，开箱即用

### 评委可能的问题及回答

| 评委问题 | 推荐回答 |
|---|---|
| 怎么保证人脸没漏？ | 用"国徽页保留 + 人像页整片打码"的简化策略——宁可多打不可漏打 |
| 财报脱敏准不准？ | 用正则匹配敏感字段；演示时附脱敏前后对比图说明 |
| 为什么要做脱敏？ | 保密合规：身份证/财报敏感不能发 AI；公开信息（企查查/工商）可发 |
| 性能如何？ | 单张身份证图片 < 1 秒；批量 9 个文件 < 2 秒 |
