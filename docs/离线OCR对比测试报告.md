# 离线 OCR 与 main 系统对比测试

测试日期：2026-09-20。测试对象为本机真实材料的固定分层样本，每种首阶段材料抽取2份，共16份。材料包括营业执照、纳税材料、ISO三体系证书、生产许可证和售后证明。原始文件、供应商名称和OCR文字没有写入报告。

## 结论

当前离线分支的文字与规则结果已经接近 main，但还不适合替代 main 自动通过材料。主要问题不是运行失败，而是置信度策略导致15/16份转人工，以及营业执照字段存在较多文字差异。

| 指标 | 离线 PaddleOCR | main / TextIn |
|---|---:|---:|
| 同批处理成功 | 16/16 | 16/16 |
| 批量平均速度 | 2.65–2.81秒/份 | 1.53秒/份 |
| 首轮冷启动参考 | 9.14秒/份 | 1.24秒/份（8份样本） |
| 自动通过 | 1/16 | 7/16（历史结构化结果） |
| 转人工或不通过 | 15/16 | 9/16（历史结构化结果） |

离线热批处理比 TextIn 慢约1.73–1.84倍。冷启动及样本页数对离线速度影响很大，因此不能只引用一次运行时间。

## 一致性代理指标

历史 TextIn 结果不是人工真值，以下数字表示两个系统是否得到相同结构化结果，不能称为真实准确率：

- 可比较字段完全一致：35/44，79.5%。
- 可比较核验项一致：34/37，91.9%。
- 在应用离线分支0.9置信度门槛后，“是否自动通过”一致：10/16，62.5%。
- 忽略置信度门槛时，业务抽取逻辑的“是否自动通过”一致曾达到15/16；但这不是分支实际行为，不能用于上线结论。

分材料看，ISO14001字段为7/7一致；ISO45001与ISO9001均为6/7；生产许可3/4；纳税材料6/7；售后材料3/3。营业执照只有4/9字段完全一致，是当前最明显短板。每类只有2份，不能据此推断总体准确率。

## 置信度问题

每份文档取最低文字框置信度后，中位数只有0.7205；16份中低于0.7的有7份、低于0.8的有12份、低于0.9的有15份。当前实现以“任何一个文字框低于0.9”整份转人工，几乎必然消灭自动化收益。

更合理的下一步是只对参与关键字段和规则判定的文字框设置信心门槛，并按字段类型设置阈值。例如信用代码、日期、等级采用较严阈值，标题或无关说明的低分不应让整份材料转人工。在没有人工标注前，不应直接把全局阈值从0.9降低后上线。

## “准确率”还缺什么

本轮没有人工逐字段标注，因此无法给出严格准确率。要形成可用于选型的数字，需要对至少每类20至30份材料标注企业名称、信用代码、注册资本、证书类型、持证主体、有效期、纳税等级和年度，并统计字段精确率、召回率、误通过率和转人工率。审批场景应优先约束误通过率。

机器可读汇总位于 `docs/offline_ocr_benchmark.json`，测试工具位于 `tools/benchmark_ocr.py`。TextIn实时测速会消耗额度，工具默认不调用，只有显式传入 `--live-main` 才会调用。
