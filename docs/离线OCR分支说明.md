# 离线材料 OCR 第一阶段

分支：`quinn5038/offline-material-ocr`。

材料解析仅使用本地 PaddleOCR 2.9.1；TextIn 入口强制拒绝，不存在云端回退。
招采材料下载和企业信息查询仍需网络，系统整体不是断网系统。

## 范围

- 身份证：沿用现有本地识别及脱敏，仅保留姓名、有效期。
- 营业执照、纳税证明、ISO9001/14001/45001、生产许可、运输许可、售后认证：本地识别并复用现有字段与规则核验。
- 授权书、售后承诺书、财报：本阶段保持人工核验。售后认证入口若实际内容为证明函，沿用现有证明函日期规则。
- 支持 PDF、PNG、JPG/JPEG、BMP。Office、GIF 等格式转人工，尚未增加表格结构模型。
- 未通过既有材料类型与敏感内容范围检查的附件仍转人工；本阶段不扩大敏感材料处理范围。

## 部署与运行

沿用 `PADDLE_PYTHON` 与 `PADDLE_MODEL_DIR` 配置。默认解释器在 `.paddle-venv`，模型目录在 `models/paddleocr`，需事先准备 det/rec/cls 模型。环境缺失时报告转人工，不调用外部服务。

首次联网部署可运行 `setup_paddle.ps1`；后续识别在工作进程内禁用出站 socket 连接。安装过程可能联网下载依赖和公开模型，处理材料时禁止自动下载。

Web 的“后台审批”和 `python textin_pipeline.py parse <todoId>` 均执行本地 OCR。历史模块与 `textin_results.json` 名称为兼容报告接口保留，并不表示调用 TextIn。

`extract` 命令只读取有效的本地 OCR 缓存，不识别新材料。缓存使用 `.local.md/.local.detail.json/.local.sha256`，匹配源文件哈希及模型权重身份；旧 TextIn 缓存不能直接复用。

一轮待解析附件批量交给一个独立进程，模型加载一次。PDF 以 200 DPI 逐页渲染，保留页码、文字框坐标和置信度。任一页无文字、超过100页或解析失败时整份材料转人工。任一识别文字置信度低于0.9或缺失置信度时增加人工核验项；此阈值属于保守试运行策略，尚未用业务样本校准。

## 验收

运行项目 pytest 测试。真实模型自检：

```powershell
& <PADDLE_PYTHON> offline_desens/material_smoke_test.py --model-dir <PADDLE_MODEL_DIR>
```

自检使用合成 PNG 和两页 PDF，在禁止联网条件下检查实际识别、页码和置信度。它不代表真实营业执照、税务、ISO等业务材料的准确率。上线前还需逐类人工标注样本，评估关键字段准确率、误通过、转人工比例和处理耗时。印章真实性、证书撤销状态无法仅凭 OCR 验证。

本机验证：144项项目测试通过；实际模型在禁止联网条件下完成合成 PNG 与两页 PDF 自检，耗时约14秒（包含模型加载，不能代表单家审批耗时）。合成样本中出现字母 O 与数字0混淆，因此未宣称业务字段准确率。

仓库现有 `dist/SupplierApproval-Setup.exe` 是旧版安装器，本次源码改造不会自动更新该文件；交付本分支源码或另行重建安装器。
