## 一、接口调用链路

系统与 ICCEC 审批系统（scpma.iccec.cn）的交互通过 7 个 API 接口完成，调用顺序如下：

| 步骤 | 接口 | 方法 | 用途 |
|------|------|------|------|
| 1 | `/apis/asca/todo/home/list` | POST | 拉取待办列表（分页，status=0 筛选待办） |
| 2 | `/apis/scpma/approve/getReq` | POST | 获取审批请求详情（拿到 supInfoApplyId） |
| 3 | `/apis/scpma/approve/queryTodomsgDetailById` | POST | 查询待办详情（补充审批流程字段） |
| 4 | `/apis/scpma/smc/qrySupRegistBaseInfo` | POST | 查询供应商基础信息（名称、法人、注册资本、经营范围等） |
| 5 | `/apis/scpma/smc/qrySupQualification` | POST | 查询供应商资质列表 |
| 6 | `/apis/scpma/smc/qrySupplierQualificationFile` | POST | 查询资质文件列表（营业执照、身份证、ISO 证书等附件） |
| 7 | `/apis/scpma/smc/qrySupFinanceInfo` | POST | 查询财务信息 |

**认证方式**：
- asca 域名：APP_TOKEN 请求头
- scpma 域名：session cookie + Authorization 令牌（cookie 会过期，约 1-3 天）

**WAF 防限流**：scpma 域名部署华为 WAF，密集请求会封禁 IP（实测>13分钟）。系统内置 REQ_INTERVAL=5s（请求间隔）和 SUPPLIER_INTERVAL=15s（供应商间隔）两道节流，超时后自动长冷却重试，仍失败则熔断退出（退出码2），进度已保存可续跑。

## 二、规则引擎设计

### 2.1 规则配置结构（rules.yaml）

```yaml
part_1_basic:          # 基础准入项
  domestic:             # 境内供应商
    - id: "A01"
      name: "营业执照"
      check_type: material   # material=材料齐全性 / field=字段判定 / conditional_material=条件材料
      rule: "supplier.has_business_license == True"
      detail: "营业执照须有效且在营"
    - id: "A02"
      name: "法人身份证"
      check_type: material
      rule: "supplier.has_legal_person_id == True"
      detail: "法人身份证须在有效期内"
    # ... A03 纳税信用、A08 财报、A10 ISO、A13 检验检测资质 等

part_2_scales:          # 规模分级（不同供应商类型不同阈值）
  trader:               # 贸易商
    min_capital: 500    # 最低注册资本（万元）
  service:              # 服务商
    min_capital: 500
  contractor:           # 承包商
    min_capital: 1000
  inspection:           # 检验检测类
    min_capital: 500
    required_certs: ["CMA", "CNAS"]

decision_logic:         # 综合决策逻辑
  hard_fail: ["应为", "已过期", "不一致", "未上传", "材料缺失", "缺少", "非经审计", "纳税申报表", "概括式"]
  # 出现这些关键词的 fail 项 → 硬伤 → 退回补材料
  # 其他 fail 项 → 软伤 → 转人工核验
```

### 2.2 沙箱求值器（eval.py）

规则表达式通过自研沙箱执行，安全约束：
- 只能读取 `supplier` 对象字段，不能调用任意函数
- 不支持 `import`、`open`、`exec` 等危险操作
- 表达式语法：`supplier.字段名 运算符 值`，如 `supplier.registered_capital >= 500`

### 2.3 三段式决策逻辑

```
check_auto_rules()     → 字段判定（注册资本、经营范围等硬指标）
build_checklist()      → 材料齐全性检查（应有但未上传 → fail）
generate_opinion_v4()  → 综合决策：
                         硬伤（HARD_FAIL_KEYWORDS 命中）→ reject（退回）
                         软伤（其他 fail）→ manual（转人工）
                         全通过 → recommend（建议同意）
```

### 2.4 OCR 增强

TextIn OCR 识别以下证件类型并抽取结构化字段：

| 证件类型 | 抽取字段 |
|----------|----------|
| 营业执照 | 注册资本、成立日期、营业期限、经营范围、法人姓名 |
| 法人身份证 | 有效期（支持"长期"识别）、出生日期 |
| 审计财报 | 报告年度（合规判定：应为今年-1年度）、经营现金流 |
| 纳税信用证明 | 评价年度（合规判定：应为今年-1年度）、信用等级 |
| ISO 体系证书 | 证书编号、有效期、持有人（与营业执照交叉核验） |
| 检验检测资质 | CMA/CNAS 证书编号、有效期、检测范围 |

## 三、部署指南

### 3.1 本地部署（推荐起步）

```bash
# 1. 克隆代码仓库
git clone <仓库地址>
cd supplier_approval_starter

# 2. 创建虚拟环境并安装依赖
python -m venv venv
# Windows
venv\Scripts\activate
# macOS/Linux
source venv/bin/activate

pip install pyyaml requests python-dotenv fastapi uvicorn jinja2 python-multipart

# 3. 配置凭证
copy .env.example .env
# 编辑 .env 填入真实值

# 4. 启动 Web UI
cd web
uvicorn app:app --host 0.0.0.0 --port 8000
```

浏览器打开 `http://localhost:8000` 即可使用。

同事通过你的局域网 IP 访问：`http://<你的IP>:8000`（查看本机 IP：`ipconfig`）。

### 3.2 内网穿透（供外部评委访问）

本地服务默认只能局域网内访问。如需让不在同一网络的评委访问（如参赛演示），使用内网穿透工具：

**方案：cpolar（推荐，免费版够用）**

1. 下载 cpolar：https://www.cpolar.com/
2. 注册账号获取 authtoken
3. 配置 token：`cpolar authtoken <你的token>`
4. 启动隧道：`cpolar http 8000`
5. cpolar 会生成一个公网地址（如 `https://xxx.r2.cpolar.cn`），把此地址交给评委
6. 评委浏览器打开即可看到你的 Web UI
7. 演示结束后关闭 cpolar 即可，地址失效

**替代方案：natapp（国内服务，速度更快）**

### 3.3 命令行运行（批处理）

```bash
# 批量处理所有待办（DRY_RUN=true 只模拟不真审批）
python auto_approve.py

# 只拉取数据入缓存，不审批（调试用）
FETCH_ONLY=true python auto_approve.py

# 只处理指定 todoId
FETCH_ONLY=true FETCH_IDS=45339209 python auto_approve.py

# 离线重算 stage2（基于缓存+企查查+OCR，不碰scpma）
python auto_approve.py --stage2

# 真实审批（确认规则无误后）
DRY_RUN=false python auto_approve.py
```

## 四、数据文件说明

| 文件 | 作用 | 是否入 Git |
|------|------|-----------|
| `rules.yaml` | 准入规则配置（核心可复用资产） | 是 |
| `.env` | 真实凭证（Cookie/Token） | 否（.gitignore 排除） |
| `.env.example` | 凭证模板（占位符） | 是 |
| `cache_v4.json` | 供应商原始数据缓存 | 否（含真实供应商信息） |
| `textin_results.json` | OCR 结构化字段 | 否 |
| `stage2_results.json` | 判定结果+审批意见 | 否 |
| `qcc_results.json` | 企查查核验结果 | 否 |
| `approval_YYYYMMDD.log` | 操作日志 | 否 |
| `files_cache/` | 下载的证件文件 | 否 |
